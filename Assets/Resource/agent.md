# 项目协作约定

## 功能实现前先读文档索引

- 每次进行功能实现、修改或修复前，必须先读取 [AIDoc/S-索引.md](AIDoc/S-索引.md)。
- 按索引选择并读取相关的用户原始文档与整理文件，再检查现有代码并开展实现；不能只看索引摘要就跳过相关规范。
- AIDoc 下不以英文字母开头的文件，按项目约定视为用户编写的原始文档；带英文字母前缀标识的文件（例如 `X-xx`、`E-xx`、`F-xx`）是经过整理的文件。
- AI 整理文件使用 `字母-标题` 命名：中文开头取首字拼音首字母，英文开头取英文首字母，均大写，例如 `Y-音效设置AI实现文档.md`、`E-Event实现说明.md`、`F-Frame框架.md`。无英文前缀的用户原文保留原名。
- 整理文档时保留用户原文，新增带标识前缀的文件；除非用户明确要求，不覆盖原始文档。
- 区分需求、方案、实现记录和历史参考；用户当前明确要求优先，文档与代码存在差异时核对说明，不仅凭前缀判断优先级。
- 新增、重命名、删除文档或改变实现状态时，同步维护索引，保持文件链接和阅读提示准确。

## 事件命名

- 事件使用 `模块名Event.On事件名` 的命名形式，例如 `LoginEvent.OnLoginDone`。
- `LoginEvent` 表示登录模块的事件集合，`OnLoginDone` 表示“登录完成”事件。
- 模块名和事件成员使用 PascalCase；事件成员以 `On` 开头，名称清楚表达动作或状态变化。
- 新增事件及编写方案、示例、文档时，优先遵循上述命名，不擅自改写为 `GameEvent.Login_Completed` 等其他风格。
- 命名形式不预先限定底层使用字符串、枚举或常量映射；具体实现以项目兼容性和轻量、便捷、简单为原则。
- 既有 `GameEvent` 调用无需仅为统一命名而批量重构；需要迁移时保留兼容路径。

## 监听代码组织

- `AddEventListener()` 是集中整理监听注册代码的普通壳方法，属于编码规范，不是生命周期接口，不需要强制覆写。
- UI 在自己的 `_FirstOpen()` 中调用该方法，Control 在自己的 `OnInitialize()` 中调用；方法可声明为 `private void AddEventListener()`。
- 不为该编码习惯在基类新增 `abstract / virtual AddEventListener()`，也不生成 `override AddEventListener()` 或自动注册约定。
- 没有监听需求的类不必声明空方法；监听的释放和执行条件由实际事件管理能力负责。

## 跨模块协作

- Event 和全局 Control 都可以用于跨模块调用与通知，不规定跨模块只能使用事件。
- 需要明确目标或同步返回结果时，可直接调用 `XxxControl.Instance` 的公开业务方法；Control 也可提供公开通知事件。
- 需要解耦、广播或通过消息提交请求时，使用 EventCenter；普通派发同步执行，派发期间产生的嵌套事件最早在下一帧执行，不能依赖嵌套事件同步返回结果。
- Control 负责业务处理与 Model 修改，Model 保持纯数据；根据实际耦合关系选择最简单的协作方式。
